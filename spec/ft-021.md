FT-021 — Instalação do Wasmtime Runtime IsoladoModule: Core Engine | Version: v0.1 | Priority: P0 — CriticalArtifact ID: FT-021-WASMTIME-SANDBOX | Updated: 2026-09-191. Context and ObjectiveO KinePlex permite que usuários submetam código arbitrário (User Defined Functions) para rodar nos nós. Se um código malicioso ou mal escrito tentar fazer um loop infinito ou estourar a memória (OOM), o nó inteiro cairia. Usamos a Wasmtime Engine para criar um Sandbox restrito em nível de instrução, garantindo isolamento total do processo Host (Rust).2. Acceptance Criteria (AC)GeneralAC-001: Thread-safe; múltiplas instâncias Wasm podem ser executadas em threads paralelas sem contenção de locks globais.AC-002: Modo JIT (Cranelift) habilitado.SpecificAC-010: Configuração de wasmtime::Config com consume_fuel(true) para limitar o tempo máximo de CPU de uma função.AC-011: Configuração rigorosa de memória limitando a alocação máxima da Linear Memory do Wasm (ex: 2GB máximo por instância).AC-012: Desabilitar módulos Wasi padrão (Wasm não deve ter acesso a disco, rede ou variáveis de ambiente do KinePlex).3. Definition of Done (DoD)Instância Singleton do wasmtime::Engine criada no boot do processo (o Engine é pesado de instanciar, deve ser reaproveitado).Testes unitários onde um Wasm propositalmente malicioso (loop infinito) gera um Trap (interrupção) limpo que é capturado e reportado, não travando a thread Rust.4. Usage ExamplesInput (Rust config):Rustlet mut config = wasmtime::Config::new();
config.cranelift_opt_level(wasmtime::OptLevel::SpeedAndSize);
config.consume_fuel(true); // Previne infinite loops
config.wasm_multi_memory(true);
